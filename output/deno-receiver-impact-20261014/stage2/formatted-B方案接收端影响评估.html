一、背景与当前接线现状（代码事实）

B 方案的初衷是解决「出厂即孤岛」：插件分发出去后，官方收不到任何使用数据，免费额度计数也没有归并通道。接收端上线后，数据流并非「全自动贯通」——三侧（l0 / full / 接收端）的接线程度各不相同，先用代码事实把现状钉住。

二、对免费插件（dsh-motor-ai-l0 0.5.0）的影响

免费插件是本次 B 方案唯一真正接线的客户端。总体判断：收益在归并与能见度，代价在隐私立场与两个口径差；限流能力本身在 0.5.0 已本地闭环，不依赖接收端。

2.1 正向影响

维度变化说明
跨机额度归并✅ 新增旁路响应若报 allowed:false 且 used > 本地计数，会把本地计数抬升——重装 / 换目录导致的清零可被追回
使用能见度✅ 从 0 到 1官方首次可观测匿名调用量（设备哈希 + 调用次数），「出厂即孤岛」在计数层面解除
延迟代价✅ 零旁路 fire-and-forget + 定时器 unref()；实测后端挂死时 checkFreeQuota 1ms 返回（探针 D3：11 次共 31ms）
功能可用性✅ 不受影响放行决策 100% 本地（free-quota.json），后端不可达 = 不归并、照常放行

2.2 需要如实告知的代价

  1. 默认即外发：freeQuotaEnabled: true + 预填地址，安装后每次工具调用向境外服务器 POST {plugin_id, device_id}（device_id = sha256(hostname|platform|arch) 前 16 位）。README 已披露、开关可关，但「默认开」本身是隐私立场选择，建议上架页再次明示。
  2. 指纹碰撞风险：3 字段指纹在同一主机名多用户场景（公用电脑、镜像克隆）会共用一本账——A 的用量会抬升 B 的计数（合并逻辑双向）。
  3. day 口径差：接收端按 UTC+8 自然日切，插件按机器本地时区切；海外用户会出现归并窗口错位（国内用户无感）。
  4. limit 口径差：接收端固定 10；插件可被 DSH_FREE_DAILY_LIMIT 覆盖，用户本地设 20 时接收端最多计到 10 ⇒ 计数低报。

三、对完整版（dsh-motor-ai）的影响

结论：当前零影响，且零风险。完整版未预填接收端地址，默认回落 127.0.0.1:5000（连接被拒即 fail-open 旁路忽略）；其放行决策本就是 100% 本地，遥测端点也无接线。也就是说，B 方案目前是免费插件专属的基础设施。

检查项状态
默认行为未预填地址 ⇒ 回落本地空端口，功能无感（full 放行决策 100% 本地）
遥测端点无接线，接收端两个端点对 full 完全闲置
激活 / License不经过接收端，无耦合
潜在风险无；唯一「影响」是 full 用户若自行配置该地址可同样获得跨机归并，但目前无文档引导

  完整版要享用接收端能力，只需随下次 full 发版在 cordis.patch.yml 预填 commerceBackendUrl（对齐 l0 的一行改动），无需改任何闸门逻辑。

四、风险与诚实边界（接收端侧）

接收端按「统计信道」标准设计，以下风险均已评估并留下缓解措施；对插件功能均不构成阻塞。

风险等级现状与缓解
端点无鉴权🟡 中任何人可打；按「统计信道」设计（append-only + 8KB~512KB 体积上限 + 每 IP 每分钟 120 次 best-effort 限流）。内嵌 key 可被 npm pack 读走，故不假装能防逆向
限流非权威🟡 中isolate 内存计数，Deno Deploy 每 isolate 独立，非权威防线
平台依赖🟡 中数据与可用性系于 Deno Deploy 免费档政策；好在插件侧失联即降级（不归并、照常放行），无单点故障
域名可达性🟢 低*.deno.net 本机直连实测 200 / 1.3s（IP 69.67.170.170 未污染）；GFW 策略若变，影响仅止于归并不止于功能
软限制🟢 低删 free-quota.json 即清零——免费档合理定位，商业版走激活码硬闸（0.5.0 docstring 已自承）

五、后续改进建议（按优先级）

七项建议按「先堵高危缺口、再对齐口径、后做运营与商业化延伸」排序；前三项建议随下一个 l0 / full 版本落地。

#优先级建议成本收益
1P0修 P0-门1：runL0Pipeline（pipeline.mjs:70）及子工具纯函数出口注入 assertFreeQuota('pipeline', config)，共用 config + 一次性消费标记防重扣小（<20 行）堵住脚本 / CI 直调零限制的唯一高危缺口
2P1full 版预填 commerceBackendUrl（对齐 l0），让完整版免费档也获得跨机归并小（一行 + 发版）两侧计数一本账
3P1口径统一：free-call 入参增加 day 字段，接收端以插件上报的 day 为 KV 键；limit 改由插件上报或请求携带中（契约双升）消除时区 / 限额低报偏差
4P2给接收端加只读聚合端点 GET /api/dsh/stats（设备数 / 调用量），替代手工查 KV小运营可观测
5P2隐私立场复核：默认外发是否需要改为「首次运行明示」小（文档 / 配置）合规稳健
6P2telemetry / experience 端点：要么接线（full 侧补 POST），要么在 README 标注「预留未启用」小消除死端点歧义
7P3长期：把接收端演进为商业后端（激活校验 / 支付回调）复用同架构；CF Worker 版保留为境外备胎（契约已逐字一致）大商业化基础设施

六、结论

B 方案走通的实质收益是「官方第一次能看见免费插件的真实使用」，且以零延迟代价、零功能风险的方式取得。免费插件的限流能力在 0.5.0 已本地闭环——这是比接收端更重要的修复；接收端补上的是归并与能见度。完整版尚未接入，建议随下次 full 发版预填地址对齐。唯一仍悬而未决的高危项是 P0-门1（纯函数脱闸），建议在下一个 l0 版本中修复。
