## 0. 结论速览

1. **机制确认（源码 + 第一方复跑双证据）**：现行 TOP 方案 = **单键排序 + TopK 纯截断 + 截断集内首个 feasible 为 recommended**。count 20→1000 后可行池涨 25 倍（150 档 94 台 → 1000 档 641 台，validate 口径），Top10 的构成从「OD 597~829 混合裁决」**塌缩为「OD 738~784 清一色大机座」**（46mm 窗口 vs 池跨径 287mm）——附件所述"三项达标小机座被挤出返回集"的机制成立。
2. **更深层发现（本次复跑新增，附件未覆盖）**：默认候选池内 **EM0103 齿磁密达标 0 台**——全池 Bt∈[0.75,0.81]，而带宽 [1.4,1.7]T。这是**上游池构造问题**（齿宽 0.5×槽距派生 ⇒ Bt=4·Bg/(π·k_stack)，选项 C 标定后 6 极 Bt≈0.75），**任何排序方案都无法把不存在的达标设计排出来**。附件中 615/54 的 Bt=1.56T 来自显式 `tooth_width=7.98mm` 通道（人工迭代产物），不是池内原生行。
3. **增强方案**（§4，编号 A~E，均附原型实测）：推荐 **E（handoff 落全池，零风险）+ C（分层配额 TopN）** 立即实施；D（双阶段约束过滤）为中期工程化方案；B（复合评分）长期需工程权重输入。
4. **L0 免费版日限**（§6）：**10 次/天本地硬闸（fail-closed）**，按调用链计次（1 次 pipeline 调用 = 1 次，与 count 大小无关）；env `DSH_FREE_DAILY_LIMIT` 可调；配额文件 `$DSH_HOME/storages/dsh-motor-ai/free-quota.json` 与完整版共用一本账。

## 1. 现行 TOP 排序机制（源码实证）

### 1.1 链路

```
buildParamMatrix(count) ──► runDesignValidate(剔 failed) ──► runL0Estimate(feasible 池, top_n, sort_by)
                                                                    │
                                                   单键排序 ──► slice(0, topN) ──► 回吐 + handoff 落盘
```

| 环节 | 实现 | 关键语义 |
|---|---|---|
| count→网格 | `param-matrix.mjs:291-295` | `perPole=ceil(count/极数)` → `axis=ceil(√perPole)` → D/L 各 axis 点，**扫描域固定 ±15%**（count 只改密度不改域） |
| 池过滤 | `pipeline.mjs:118-120` | 仅剔 validate 级 failed；passed+warning 全进池 |
| 排序 | `l0-estimate.mjs:149-152,404-407` | **单键**；白名单 efficiency/efficiency_raw/torque_density/temp_rise/total_loss/power（默认 efficiency）；temp_rise/total_loss 升序其余降序 |
| 截断 | `l0-estimate.mjs:409-410` | `topRows = results.slice(0, topN)`，**topN 默认 10** |
| recommended | `l0-estimate.mjs:420` | 截断集内**首个** `feasible===true` |
| 落盘 | `pipeline.mjs:261` | handoff 只写 `estimate.results`（=TopN）——**完整可行池不落盘，截断即真正丢失** |

### 1.2 count=1000 改变了什么（和不改变什么）

- **不改变**：扫描域（±15%）、门禁判据、每次调用的配额成本（1 次）。
- **改变**：采样密度（150→axis=13/步长 17.5mm；1000→axis=32/步长 6.8mm）⇒ 可行池规模 ⇒ **可行池从"小于截断窗口"进入"远大于截断窗口"的区间**，单键序从此决定可见性。

## 3. 根因分层（决定增强方案的作用面）

| 层 | 问题 | 本次可修？ |
|---|---|---|
| **L1 排序/截断层** | 单键排序 + TopK 纯截断 + handoff 不落全池 ⇒ 池越大可见集越窄越同质 | ✅ 方案 C/E 直接修 |
| **L2 池构造层** | 齿宽 0.5×槽距派生 ⇒ Bt=4·Bg/(π·k_stack)≈0.75~0.81（选项 C 后仍远低于 [1.4,1.7]）；矩阵生成不含 tooth_width 维度 ⇒ 达标设计从未进池 | ⚠ 需矩阵维扩展（tooth_width 候选列）或 MD-SDE 侧口径核对 |
| **L3 判据层** | EM0103 带宽 [1.4,1.7] 上界 1.7T **超出 65 台真值最大 1.47T**（p2_tooth_stamp_rootcause_report.md §7 已存疑） | ⚠ 需 MD-SDE 侧确认带宽口径 |

**给用户的直白结论**：只增强 TOP 排序，最多让"池内已有的好设计"可见；要让"三项达标"设计出现在返回集里，必须同时在 L2（把 tooth_width 通道变成池的一个维度）或 L3（重审带宽）上动作。这与附件"Pareto 冲突非迭代可解"的结论互为印证——冲突的一部分其实在池构造层就注定了。

## 4. TOP 排序增强方案（编号选项，附原型实测）

以下方案均在探针内以**原型演算**验证（未改插件），评判标准：Top10 的 OD 跨径（多样性）、达标台数、效率损失。

| 方案 | 做法 | 150 档 Top10 OD | 1000 档 Top10 OD | 达标台数* | 评价 |
|---|---|---|---|---|---|
| 现行（基线） | efficiency 单键 | 597~829 | 738~784 | 0/0 | 池大即塌缩 |
| **A 合规优先** | 达标数降序 → 效率降序 | 597~829 | 738~784（退化为纯效率序） | 0/0 | **池内无达标行时完全退化**，不可单独依赖 |
| **B 复合评分** | 0.35·norm(eff)+0.25·norm(−温升)+0.20·norm(−By)+0.20·Bt 带距，min-max 归一 | 627~748 | 703~784 | 0/0 | 有中度分散效果；权重需工程输入，标量化掩盖 Pareto |
| **C 分层配额** | OD 三分位分桶 → 桶内效率序 → 轮询取 10 | 597~829 | **597~784** | 0/0 | **唯一与池构成无关、 guaranteed 跨尺寸多样性**；小机座（597/609/632）回到可见集 |
| **D 双阶段** | 先按硬约束（EM 带宽）过滤，池空则显式回退全池并告警 → 再排序 | — | — | 取决于 L2 修复 | 工程语义最正（先达标再选优）；须带宽入参 |
| **E 落盘全池** | handoff 增写完整可行池（或全量矩阵引用） | — | — | — | **零风险、无排序语义变更**；截断行可恢复，模型可按需读取 |

\* 达标 = Bt∈[1.4,1.7] ∧ By<1.5 ∧ fill≤0.78（本地可溯源判据；本次两池均为 0，见 §3-L2）。

### 推荐组合（按优先级）

1. **E + C（立即，低风险）**：E 保证"截断≠丢失"（一行 JSON 写入 + 文档）；C 保证"返回集跨尺寸分层"（桶边界用 OD 三分位，无魔数）。两者都不改排序语义、不动任何判据，回滚 = 删一个开关。
2. **D（中期）**：把 EM0103/0105/0106 带宽作为可选入参（`em_bands`），双阶段过滤 + 空池显式回退；与 L2/L3 的修复联动生效。
3. **B（长期）**：复合评分的权重应由你按工程优先级指定（效率/温升/磁密/成本），我不预设——这正是附件"F 由 TH 主导与三项警告冲突"在 L0 层的同构问题。

### 附带发现（排序白名单）

现行 `sort_by` 白名单 6 个键全是单目标。建议扩展 `composite`/`compliance` 两个枚举值落地上述 B/A 方案（schema 一处 + sortKey 分支 + 门禁），而不是让调用方自己传权重字符串（注入面）。

## 5. 与选项 C（今日 core 1.5.2）的联动

- **已缓解**：1000-池 Top10 的 By（实际口径）从附件时代的 ≥1.5 降到 **1.11~1.35**（6 极 Bg 0.80→0.575 的直接效果）——EM0105 高压组在默认池已大幅收敛。
- **未触及**：OD 塌缩（738~784）与 Bt 不可达（≤0.81）与 Bg 标定无关，分别属于 L1/L2 层。
- **副作用提示**：选项 C 使异步机匝数 +29~50%、fill 上移——本次池 fill 上限 0.56（V15 门 0.78 内），但 1000 档 validate 失败 359 台（35.9%）高于 150 档的 37.3%→相近；若后续 L2 加入 tooth_width 维度，fill 将同步上移，须复检 V15。
